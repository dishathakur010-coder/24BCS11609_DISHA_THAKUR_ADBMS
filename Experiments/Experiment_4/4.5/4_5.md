# 1️⃣ Employee and Manager Names (Self Join)

### SQL Query

```sql
SELECT
    e1.employee_name AS Employee,
    e2.employee_name AS Manager
FROM employees AS e1
LEFT JOIN employees AS e2
ON e1.manager_id = e2.employee_id;
```

### Explanation

- A **Self Join** joins a table with itself.
- `e1` represents the employee.
- `e2` represents the employee's manager.
- `LEFT JOIN` ensures employees without a manager (e.g., CEO) are also displayed with `NULL` as the manager.

# 2️⃣ Every Possible Customer–Product Combination (Cross Join)

### SQL Query

```sql
SELECT
    c.customer_name,
    p.product_name
FROM customers AS c
CROSS JOIN products AS p;
```

### Explanation

- `CROSS JOIN` creates the Cartesian Product of two tables.
- Every customer is paired with every product.
- If there are **m** customers and **n** products, the result contains **m × n** rows.

# 🔄 JOIN Comparison

| JOIN Type | Description |
|-----------|-------------|
| **INNER JOIN** | Returns only matching rows from both tables. |
| **LEFT JOIN** | Returns all rows from the left table and matching rows from the right table. |
| **RIGHT JOIN** | Returns all rows from the right table and matching rows from the left table. |
| **FULL OUTER JOIN** | Returns all rows from both tables. |
| **SELF JOIN** | Joins a table with itself. |
| **CROSS JOIN** | Returns every possible combination of rows from both tables. |

---

# 💡 Key Points

### Self Join

- Uses the same table twice with different aliases.
- Commonly used for employee-manager or parent-child relationships.

### Cross Join

- Produces all possible combinations.
- Does not require an `ON` condition.
- Result size = Rows in Table A × Rows in Table B.

---

# ⏱️ Time Complexity

### Self Join

- **O(n²)** without indexes.
- Optimized significantly with indexes on join columns.

### Cross Join

- **O(m × n)**

where:

- `m` = number of customers
- `n` = number of products
